# Keyboard Warrior — v1.0 Product Requirements Document

**Version:** v1.0
**Project Type:** Typing + Beat-'Em-Up Game
**Target Platform:** Windows
**Engine:** Godot 4.x
**Primary Language:** GDScript
**Development Level:** Beginner Game Developer
**Future Direction:** AI / ML / LLM / Agent integration in v1.1+

---

# 1. Product Vision

Build a simple playable typing-combat game where the player controls a stickman fighter and defeats enemies by typing words correctly and quickly.

### Core Gameplay

```text
Enemy appears
      ↓
Word appears
      ↓
Player types word
      ↓
Typing accuracy/speed calculated
      ↓
Character performs attack
      ↓
Enemy takes damage
      ↓
Combo increases
      ↓
Next enemy / wave
```

The v1.0 goal is **not to create a huge game**.

The goal is:

> "Create a small but genuinely playable typing combat game."

# 8. Typing System

This is the most important system.

### Flow

```text
Word Manager
     ↓
"DESTROY"
     ↓
Typing Manager
     ↓
D → E → S → T → R → O → Y
     ↓
Validation
     ↓
Perfect / Good / Miss
     ↓
Combat
```

### Track

* Current word
* Typed characters
* Accuracy
* Typing speed
* Completion time
* Mistakes
* Combo

---

# 9. Combat System

Example:

```text
Word completed
      ↓
Check accuracy
      ↓
Calculate attack power
      ↓
Play animation
      ↓
Hit enemy
      ↓
Apply damage
      ↓
Update combo
```

### Example

| Performance   | Attack   |
| ------------- | -------- |
| <70% accuracy | Weak     |
| 70–89%        | Normal   |
| 90–99%        | Strong   |
| 100%          | Critical |

This gives typing skill a direct gameplay impact.

---

# 10. Combo System

Example:

```text
Word 1 → Hit
Word 2 → Hit
Word 3 → Hit
Word 4 → Critical

COMBO ×4
```

Combo breaks when:

* Player makes too many mistakes
* Player takes damage
* Word timeout occurs

---

# 11. Enemy System

Start with **2–3 enemies**.

### Enemy 1 — Basic

```text
Find player
↓
Move toward player
↓
Attack
↓
Take damage
↓
Die
```

### Enemy 2 — Fast

* Low HP
* High movement speed
* Frequent attacks

### Enemy 3 — Heavy

* High HP
* Slow movement
* Strong attack

---

# 12. Enemy AI

Don't use an LLM for enemy movement in v1.0.

Use a simple **Finite State Machine**.

```text
IDLE
 ↓
CHASE
 ↓
ATTACK
 ↓
HIT
 ↓
STUN
 ↓
DEAD
```

This is faster, cheaper and easier to debug.

---

# 13. Wave System

Instead of creating many levels, use one arena with waves.

```text
Wave 1
  ↓
3 Basic enemies
  ↓
Wave 2
  ↓
2 Basic + 1 Fast
  ↓
Wave 3
  ↓
2 Fast + 1 Heavy
  ↓
Boss
  ↓
Victory
```

This keeps v1.0 manageable.

# 18. v1.0 Definition of Done

v1.0 is complete when a player can:

1. Open the game.
2. Start a game.
3. Control the stickman.
4. See an enemy.
5. Receive a word.
6. Type the word.
7. Attack the enemy.
8. Damage the enemy.
9. Build a combo.
10. Defeat enemies.
11. Complete waves.
12. Lose if HP reaches zero.
13. Finish the game.
14. See score, WPM and accuracy.
15. Restart and play again.

### v1.0


```text

Player Data ─┼── LLM Word Generator

             └── AI Game Agent

                       ↓
```

# 21. Backend — Important Decision

For **v1.0: NO backend is required.**

Don't build:

```text
Godot → API → Database
```

just because you're used to web development.

Build:

```text
Godot
  ↓
Local Game Systems
  ↓
Local Data
```

Later, when AI is introduced:

```text
Godot Game
     ↓
FastAPI Backend
     ↓
AI/ML Services
     ↓
LLM / Agent
```

This keeps v1.0 simple while preserving a clean path toward an AI-powered v1.1.

```text
                             │
             ┌───────────────┴───────────────┐
             │                               │
       PRESENTATION                       GAME CORE
             │                               │

      │      │      │             │         │         │
     UI   Player  Enemy         Typing    Combat     AI
      │      │      │             │         │       (FSM)
      └──────┴──────┘             │         │
             │                    └────┬────┘
             │                         │
             └──────────┬──────────────┘
                        │
                    GAME DATA
                        │
             ┌──────────┼──────────┐
             │          │          │
           Words      Enemies    Attacks
```

### Your development rule

**v1.0 = Game first.**
**v1.1 = AI second.**
**v1.2 = Visual/gameplay polish.**

That way you learn game development without getting buried in LLMs, agents, APIs and backend work too early.
